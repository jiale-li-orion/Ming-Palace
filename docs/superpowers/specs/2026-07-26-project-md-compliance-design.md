## 3. 总体方案

采用增量修复，不重写现有架构。保留以下边界：

- `domain/`：状态、事件、路线、场景和会话摘要等纯 Dart 规则。
- `application/`：体验引擎、音频协调和操作员用例。
- `infrastructure/`：本地内容、会话、遥测与导出实现。
- `presentation/`：单屏状态驱动渲染、恢复提示和操作员面板。

新增或强化一个应用级协调边界：界面只发送带数据的用户意图，体验引擎负责校验和状态转换，专门的应用服务负责持久化、音频与导出副作用。Renderer 不直接读写文件，也不直接调用 `just_audio` 或 `share_plus`。

所有修复按“可构建闭环 → 体验闭环 → 数据闭环 → 恢复闭环 → 验收闭环”推进。每一阶段先证明当前失败，再做最小实现并重新验证。

## 4. 构建与平台设计

补齐标准 Flutter Android 工程，包名使用项目现有命名语义，最低 Android API 为 26。平台工程只包含离线 Demo 所需配置，不增加网络权限或不在范围内的插件。

`pubspec.yaml` 只保留实际使用的 `just_audio`、`path_provider`、`share_plus` 和 `uuid`。`pubspec.lock` 应纳入版本控制以固定应用依赖；构建缓存继续忽略。

构建验收顺序为：

1. `flutter pub get`
2. `dart format --output=none --set-exit-if-changed lib test integration_test`
3. `flutter analyze`，要求无 error；低价值 info 不作为功能阻断，最终再按成本清理。
4. `flutter test`
5. `flutter build apk --debug`

## 5. 状态机与体验流程

状态枚举继续以 `Project.md` 的 21 个状态为唯一集合。转换表保持集中管理，并显式区分三类结果：

- 合法转换到下一状态；
- 合法但保持当前状态，例如暂停、重播、导出；
- 非法动作，拒绝并记录 `invalid_transition`。

正常路线与替代路线共享前段、提问和结束流程，但提问合流后的去向必须依赖当前路线：正常路线进入下楼与穿门，替代路线直接进入午门南侧结束。不能通过复制页面或临时跳过实现。

`minimumDurationMs` 在应用层统一执行。达到最小时长前，普通用户的推进按钮禁用；操作员强制跳转不受此限制，但必须记录。`autoAdvance` 只由一个计时器来源触发，避免 Renderer 与 Screen 重复计时造成双转换。

进入带音频状态时由协调层加载并播放对应资源。音频完成只在转换表允许时推进；行走、安全和必须人工确认的状态不会因音频完成自动跨越。连续点击和重复完成事件通过“当前状态 + 正在转换”保护去重。

## 6. 内容配置与资源

`experience.json` 继续作为离线内容入口。每个状态必须提供：

- `id`
- `renderer`
- `audio`
- `visualSequence`
- `allowedActions`
- `next`
- `operatorActions`
- `safetyMode`
- `autoAdvance`
- `minimumDurationMs`

加载器校验顶层版本、21 个场景是否齐全、状态 ID、Renderer 类型、动作名称、目标状态、非负时长、音频路径和视觉层字段。错误信息包含 JSON 字段路径与场景 ID；配置错误阻止开始，但保留日志导出能力。

图片路径和音频路径统一采用相对 `assets/` 的形式。缺失图片显示包含资源名和 `PLACEHOLDER` 的高对比占位画面并记录 `asset_missing`；缺失音频显示可读提示、记录 `audio_load_failed`，允许普通用户继续或操作员跳过，不崩溃。

占位图片按 1080×1920、sRGB、单张不超过 2 MB 制作，并保留上下各 12% 安全区。补齐 `fade_mask.webp`。音频无法凭空生成正式内容，因此保留明确的占位清单；代码必须在没有 MP3 时仍可完成两条路线。

## 7. 音频与生命周期

音频控制器负责播放、暂停、继续、重播、停止、跳转和完成通知。应用层负责把播放器事件转换为遥测与体验事件。

应用进入后台或收到 inactive/paused/detached 生命周期时：

1. 暂停当前音频；
2. 保存当前状态、路线、会话 ID、音频资源和播放位置；
3. 记录 `app_backgrounded`；
4. 不改变体验状态。

返回前台时保持暂停，显示“继续播放”而不是自动播放。应用重新启动且存在未完成会话时，先显示恢复选择：

- 继续上次测试：恢复会话、路线、状态和音频位置，等待用户点击继续；
- 放弃并创建新会话：记录原会话中止，清理旧状态并创建新会话。

完成或操作员结束会话后清理恢复文件，但不清除遥测历史。

## 8. 会话、问卷与遥测

会话仓库只负责会话身份和恢复快照，不直接写遥测文件。体验引擎通过单一 `TelemetryRepository` 写事件，避免两个写入方产生不一致格式。

每条 JSONL 统一包含：

- `schemaVersion`
- `sessionId`
- UTC `timestamp`
- `event`
- 当前 `state`
- `payload`

必须覆盖规范列出的会话、状态、点击、操作员、音频、问题、替代路线、帮助、错误、问卷、完成和中止事件。状态转换写成成对的 `state_exited` 与 `state_entered`，或由摘要器明确兼容统一的 `state_transition`；最终文档与代码只能保留一种权威格式。

问卷提交事件必须携带三个文本答案和两个布尔答案。提交成功后才能进入 `COMPLETED`；写入失败时保留表单内容并显示重试。

会话摘要从同一事件结构计算，包含持续时间、路线、问题选择、帮助次数、中断状态和问卷。事件负载字段与摘要解析必须由测试锁定，避免当前“写在顶层、读 `payload`”的错配。

## 9. 导出与操作员功能

导出服务提供：

- 当前会话摘要与事件导出；
- 全部会话事件导出；
- 调用系统分享面板分享生成文件。

导出文件写入应用可访问的临时或文档目录，文件名包含时间和会话短 ID。导出失败显示错误并写遥测。

隐藏操作员面板继续由标题连续点击 7 次打开，并补齐以下真实用例：

- 创建新会话；
- 查看当前状态和会话摘要；
- 上一步、下一步和跳转到指定状态；
- 重播当前音频；
- 标记用户需要帮助；
- 仅在路线决策状态选择正常或替代路线；
- 结束当前会话；
- 查看日志；
- 导出当前/全部日志；
- 二次确认后清空测试数据。

每个操作先写 `operator_action`，再执行，并记录成功或失败。危险操作必须要求确认，避免现场误清空。

## 10. UI 与现场可读性

保留单屏、状态驱动 Renderer。欢迎、行走、安全、城台复原、提问、问卷、完成和错误页面分别承担一种职责。

户外直射光环境下采用高对比、较大点击区域和简短文字。安全状态使用低干扰背景和大字“请看脚下”，不显示复原图、不播放主要叙事。行走页面不显示大段台词。

城台观察状态先保持 10–15 秒无台词观察，再进入主独白。分层图像按配置淡入。结束阶段保留现实午门背景并执行 5 秒环境静默；淡出遮罩用于视觉收束。

用户级错误采用可恢复提示：重试、继续无音频、使用占位图或联系操作员。内部异常不直接显示堆栈。

## 11. 验证策略

测试不追求覆盖所有 Widget 细节，只覆盖高价值合同：

- 纯 Dart 状态机：两条完整路线、两个问题分支、非法转换、路线合流、最小时长和重复事件。
- 内容解析：完整配置、缺字段、非法状态、非法动作和无效资源描述。
- 数据层：恢复快照、统一 JSONL、会话摘要、问卷、当前/全部导出和清空。
- Widget：欢迎页、安全页、问题页、问卷数据提交、配置错误页、恢复选择和 7 次点击打开面板。
- 集成：正常路线选择削藩、替代路线选择经典，两条均完成问卷并生成可解析日志；测试使用可控的假音频和临时仓库，不依赖正式素材。

此外进行 Android Debug APK 构建。真机上的断网、后台恢复、两条路线、10 次连续运行、15 秒内重置和户外可读性属于手工验收，结果记录在仓库文档中，不以自动化测试代替。
